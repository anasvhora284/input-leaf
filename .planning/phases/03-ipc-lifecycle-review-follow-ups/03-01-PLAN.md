# Plan 03-01: IPC Lifecycle & Review Follow-ups

<objective>
Harden IPC lifecycle reliability and resolve all review findings from collaborator Issue #52:
1. Introduce monotonic generation tokens in `InputInjectorService.attachClient` so stale death notifications from replaced client tokens do not tear down active devices (IPC-01, #52).
2. Fix `HidMouseEnterWarp` to accurately return only applied plans on partial writes, clear/advance pending state to avoid double-applying snaps, align clock source to `SystemClock.uptimeMillis()`, guard against `NaN` in `MousePointerCompensation`, and clamp wheel notches (IPC-02, #52).
3. Document stable AIDL transaction code ordering in `IInputInjector.aidl`, sanitize markdown links in `MarkdownContent`, ensure thread visibility for `ConnectionService` jobs, fix `UHID_OUTPUT` KDoc, and maintain zero emojis (IPC-03, ARCH-02, #52).
</objective>

<context>
Issue #52 tracks follow-up items from the 1.4.2 review by collaborator @guaje. In particular, asynchronous Binder death notifications are susceptible to race conditions when a client reconnects quickly; `HidMouseEnterWarp` previously re-sent full snap plans even if prefix packets were already written; `MousePointerCompensation` threw on `NaN`; and markdown URLs with titles were malformed.
</context>
