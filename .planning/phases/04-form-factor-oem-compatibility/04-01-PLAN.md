# Plan 04-01: Form-Factor & OEM Compatibility

<objective>
Expand Input Leaf Android's hardware and OS compatibility to Huawei tablets, Android TV, and absolute digitizer pens:
1. Fix connection crashes on Huawei MatePad SE 11 by hardening screen bounds detection, WindowManager access from background service contexts, and foreground service initiation (OEM-01, #54).
2. Add full Android TV support with Leanback banner metadata, non-mandatory touchscreen feature declarations, and D-pad key routing (OEM-02).
3. Implement user-selectable Pointer Device (Relative Mouse vs Absolute Stylus/Pen) with `HidPen` absolute digitizer injection and unit testing (OEM-03, ARCH-02).
</objective>

<context>
Issue #54 tracks crashes on Huawei MatePad SE 11 when attempting to connect. Non-visual contexts calling `WindowManager.currentWindowMetrics` throw on Android 11+ / EMUI tablets, and missing foreground service type parameters or display insets cause fatal exceptions. Meanwhile, users requesting Android TV and tablet stylus support need clean Leanback declarations and absolute digitizer coordinate scaling.
</context>

<task id="04-01-01" name="Harden ConnectionService and CursorOverlayService against Huawei tablet crashes" type="tracer">
  <read_first>
    app/src/main/java/com/inputleaf/android/service/ConnectionService.kt
    app/src/main/java/com/inputleaf/android/service/CursorOverlayService.kt
  </read_first>
  <action>
    1. In `app/src/main/java/com/inputleaf/android/service/ConnectionService.kt`:
       - Refactor `getScreenBounds(): Rect` to use a robust 3-tier cascade:
         * Tier 1: `runCatching { wm?.currentWindowMetrics?.bounds }`
         * Tier 2: `runCatching { displayManager?.getDisplay(Display.DEFAULT_DISPLAY)?.getRealSize(...) }`
         * Tier 3: `resources.displayMetrics` (`widthPixels`, `heightPixels`)
         * Coerce dimensions to at least `1x1` to prevent divide-by-zero or non-positive metrics.
       - In `performConnect`:
         * Wrap `startForeground` in `runCatching` using `ServiceCompat.startForeground` with `FOREGROUND_SERVICE_TYPE_CONNECTED_DEVICE` so background starts on strict OEMs log warnings rather than crashing.
    2. In `app/src/main/java/com/inputleaf/android/service/CursorOverlayService.kt`:
       - Wrap `windowManager?.addView` and `windowManager?.updateViewLayout` in defensive try-catch blocks to catch `BadTokenException` and `SecurityException`.
    3. Add unit test `ConnectionServiceBoundsTest.kt` verifying fallback behavior when `WindowManager` is absent or throws.
  </action>
