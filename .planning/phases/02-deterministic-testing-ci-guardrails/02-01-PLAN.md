# Plan 02-01: Deterministic Testing & CI Guardrails

<objective>
Eliminate test flakiness, eliminate all wall-clock sleeps, decouple UI testing from physical hardware/network, and enforce strict coverage guardrails:
1. Replace all `Thread.sleep` and wall-clock assertions in JVM unit tests (`InputInjectorServiceEnterTest.kt`, `HidAttachmentControllerTest.kt`, `UhidChannelReadinessTest.kt`) with virtual clocks (`UhidReadinessConfig`) and coroutines test synchronization (TEST-01, #51).
2. Introduce a lightweight `AppDependencies` provider and `TestAppDependencies` fake to isolate `MainActivity` and `MainViewModel` from hardware, and add the headless Android smoke test workflow `.github/workflows/android-smoke.yml` (TEST-02, #13).
3. Enforce 100% patch test coverage on core protocol and UHID drivers via Kover verification (`koverVerifyDebugJvm`) and unignoring UHID in `codecov.yml` (TEST-03, #13, #51).
</objective>

<context>
docs/TESTING.md establishes strict guidelines: tests must control time, asynchronous work, and dependencies explicitly without arbitrary sleeps or reliance on real LAN/hardware. Issue #51 highlighted that `InputInjectorServiceEnterTest` and `HidAttachmentControllerTest` violated these principles by using `Thread.sleep` and wall-clock elapsed timing. Issue #13 laid out the complete architecture for headless emulator smoke testing using manual dependency injection (`AppDependencies`, `MainViewModelFactory`, `TestAppDependencies`) and a dedicated GitHub Actions workflow.
</context>
