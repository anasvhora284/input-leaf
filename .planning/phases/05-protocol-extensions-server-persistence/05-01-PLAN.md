# Plan 05-01: Protocol Extensions & Server Persistence

<objective>
Enable seamless connectivity with Synergy 3.7+ desktop servers and guarantee persistent server list storage across application restarts:
1. Complete Synergy 3.7+ protocol handshakes on `DSOP` after `DINF`, decode signed 16-bit relative mouse deltas (`DMRM`), and explicitly report refusal codes (`UNKNOWN_SCREEN`, `PROTOCOL_ERROR`) without auto-retrying permanent failures (PROT-01, #47, #53).
2. Translate Mac Carbon physical keycodes to Linux evdev scancodes, support multi-source adaptive encoding learning (`EVDEV`, `X11`, `MAC`), and maintain pressed key release tracking to eliminate stuck keys (PROT-02, #53).
3. Persist manually added, connected, and favorited servers in DataStore (`saved_servers`), recover historical addresses from legacy records, and merge saved servers with live mDNS discovery in `MainViewModel` (PROT-03, ARCH-02, #53).
</objective>

<context>
Synergy 3.7.2 on macOS communicates with Input Leaf over TCP 24800 using standard TLS/mTLS encryption, but differs in handshake timing (it sends `CIAK` before verifying the screen, only confirming session acceptance on `DSOP` or refusing with `EUNK`), motion packet size (4-byte signed 16-bit relative deltas), and keycode encoding (Carbon virtual keycodes offset by +1). Furthermore, manually added server addresses currently vanish upon app restarts because they were not persisted to DataStore.
</context>
